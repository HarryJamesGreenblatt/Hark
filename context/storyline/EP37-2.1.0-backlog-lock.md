The **locked 2.1.0 scope** (six items):

1. **Rebrand: HARK = "Hear · Adapt · Render · Keep."** The backronym now fits the post-Vision product
   (Hear = capture, Adapt = diarize/refine/name, Render = the Vision crystal ball, Keep = save/multi-format
   export). A single coordinated **scrub** across code + docs (README, this storyline snapshot, north-star
   docs, in-app copy, any tagline). Purely presentational; no runtime risk.

2. **Organic eye motion (research-grade).** Give the Vision eye life beyond dilation/highlight: (a) **gaze /
   look-at** (follow the mouse when it hovers a mind-map node), (b) **audio-reactive on a new band** (a third
   band → saccade energy, orthogonal to bass→dilation / treble→highlight), (c) **attraction/repulsion** with
   pills/cursor. The "unconvincing in 2D" worry is answered by the standard **layered pupil-offset** look-at
   (translate the inner pupil group within the clipped cornea) — a channel orthogonal to the existing ones.
   First step is a **research spike** (oculomotor saccade/fixation models; procedural gaze — Andrist/Mutlu;
   Perlin's Responsive Face; force-directed / potential fields, which reuse the project's own physics idioms),
   not a big build.

3. **Generated report/deck title.** Replace the hardcoded `"Hark session report"` in
   `OverlayWindow.BuildSessionReport()` (~L1914) — it flows to **every** format via `SessionReport.Title`, so
   one fix upgrades HTML/Markdown/Word/PDF and the **PPTX** title slide + hero. Seam: piggyback the existing
   `ReportRecapsRequested` on-save event. Cheap option: derive from the `MeetingRecap` overview / dominant
   beat topic; better: a tiny strict ≤~8-word AOAI title call — with a graceful fallback to the static string.

4. **PDF export in light mode.** `PdfReportWriter` prints the **dark** HTML via WebView2 `PrintToPdfAsync`,
   which renders onto **white** PDF pages → a jarring white page-margin border around dark content. Fix: a
   **light printable surface** for the PDF (mirroring `DocxReportWriter`) via a new `lightMode`/`forPrint`
   flag on `HtmlReportWriter.Render`/`Build` (same pattern as the existing `transcriptOpen`); only the PDF
   path passes it, the web page stays dark.

5. **Consistent HAL icon across exports.** Today the mark is inconsistent — **HTML/PDF** use a CSS
   radial-gradient faux-eye, **Markdown** and **Word** omit it, **PPTX** uses the first scene as the hero. The
   real asset exists (`Hark.App/Assets/Icon.png`, the EP13 icon set). Embed it as a **shared hero mark** in
   every writer (base64 HTML/PDF, inline PNG in Word, a small mark on the PPTX title slide, data-URI in
   Markdown with the renderer caveat), with a small asset-plumbing decision (add the PNG to `SessionReport`
   or a shared loader) and a no-mark fallback.

6. **Installer: long delay before the UAC prompt.** Since the WinForms→WPF single-file rewrite (EP28) there's
   a long "nothing's happening" gap before UAC. **Not** reverting to WinForms (its cross-machine DPI mushing
   was the reason for the rewrite). The user's design: an instant **splash** that the ready WPF window
   replaces. See the honest cause read below — the plan is **measure first**, then combine the splash
   (post-UAC) with bundle/startup tuning (pre-UAC).

## 🧠 Decisions
- **Compile then lock, don't drip-implement — because** the user wanted a cohesive 2.1.0 milestone, and
  grounding each item in code up front (exact files/seams) makes the eventual build faster and avoids
  relitigating scope.
- **The rebrand leads — because** it's the cheapest, highest-identity change and reframes how every other
  artifact is described (do it as one pass, not piecemeal).
- **Organic eye motion is a spike, not a feature commit yet — because** the "convincing 2D gaze" question is
  genuinely research-shaped; prove the motion model with one live look before committing to the full build.
- **Fix the title once in `BuildSessionReport` — because** `SessionReport.Title` fans out to all five formats;
  a single seam upgrades every export.
- **PDF goes light, web stays dark — because** the white PDF page is fixed by matching content to a light
  printable surface (what Word already does), while the interactive web page keeps the app's dark identity.

## 🚧 Problems & resolutions
- **Symptom:** the installer shows a long dead gap *before* the UAC prompt → **Root cause (to verify):** the
  manifest is `requireAdministrator`, so **UAC fires at CreateProcess before any managed code runs** — a
  managed splash *cannot* draw before UAC. The pre-UAC delay is almost certainly OS
  Authenticode/SmartScreen/AV verification **+ single-file self-extraction cold-start** of the large
  self-contained WPF exe. → **Fix direction:** the proposed splash covers the **post**-UAC WPF cold-start
  (real but secondary); the **pre**-UAC gap needs ReadyToRun / extraction tuning / framework-dependent (risky)
  / **Trusted Signing** to cut SmartScreen — **measure where the seconds go first**, don't guess.
- **Finding (branding):** the report title is hardcoded `"Hark session report"` (not the `"session notes"`
  first recalled) — grep-grounded to `OverlayWindow.BuildSessionReport()`.
